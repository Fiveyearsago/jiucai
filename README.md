# Beauty 注册助手（macOS）

原生 SwiftUI 客户端，通过 URLSession 直接请求韭菜盒子注册接口，在表单中完成邮箱验证和注册。支持自动读取 Fviainboxes 临时邮箱，也可手动输入验证码。适用于 macOS 13 及以上；代理功能需要 macOS 14 及以上。当前构建适用于 Apple Silicon。

## 运行

双击 `dist/Beauty 注册助手.app`。从源码构建需要 Xcode Command Line Tools：

```sh
./scripts/build-app.sh
```

### 注册单个账号

1. 在“注册工作台”填写用户名、邮箱、8–128 位密码和邀请码（可选）。工作台显示当前代理和接口连接状态，可点击“检查连接”或“任务 → 检查接口连接”进行只读检查。
2. 使用 `@fviainboxes.com` 临时邮箱时，可启用“自动读取临时邮箱验证码”，并阅读、同意侧边栏中的邮箱服务条款。使用其他邮箱或自行收信时，关闭自动读取。
3. 点击“请求验证码”。邮件中的 6 位验证码可自动填入，也可手动输入字母和数字验证码；等待期间始终保留手动补填入口。
4. 确认验证码后，点击“注册用户”提交。单个账号取得验证码后仍需手动点击此按钮。
5. 在“注册记录”查看结果、请求详情或导出 CSV；“记录目录”可打开本地数据文件夹。

客户端不会绕过注册接口或邮箱服务的人机验证。接口、人机验证状态或邮箱读取失败时，任务记录原因并自动切换下一个代理，重新进行当前账号的注册流程；一轮失败后自动等待下一轮。客户端保持运行，可以手动停止并调整收码方式。确认发码后正常等待新邮件期间只查询邮件，不重复发送验证码。

### 批量注册

在侧边栏设置用户名前缀、起始编号、编号位数、注册数量、密码、邀请码和账号间隔，然后点击“开始批量注册”。默认起始编号为 176、数量为 1；请按实际账号使用情况调整。账号间隔默认 60 秒，可设置为 3–3600 秒。

批量任务按顺序生成用户名及 `@fviainboxes.com` 邮箱，自动请求验证码、读取邮件并提交注册；无法自动收码时可手动补填。单次注册数量可为正整数，仍校验整数溢出和用户名长度。大批量任务只规划编号范围，在开始某个账号时才创建其记录。

运行中的请求失败不会自动暂停、弹窗或结束任务。任务持续处理到所有计划账号均成功或留为待核对。用户主动暂停后不发起新的流程动作，已经发出的网络请求仍可能完成；用户主动停止会取消后续任务。

## 代理池

代理支持每行一个 `host:port` 或 `host:port:user:password`。启用后按列表使用，并按配置的账号数量轮换。

- **批量测试门槛**：默认 3000 ms，可改为正整数；超过门槛、超时或不可用的代理自动从列表删除。
- **使用前测速门槛**：默认 5000 ms，可改为正整数。每个账号使用代理前都重新测速，必须严格低于门槛才使用，否则删除并按列表顺序测试下一个代理。
- **测试并发**：默认 5 个，可设置为 1–20 个。其余代理排队，排队时间不计入延时。支持进度显示和停止测试；开始注册会先停止批量测试，再进行使用前复测。
- **接口请求超时**：默认 10 秒，可改为正整数并自动保存。接口请求超过设定时间未完成时，删除当前代理，复测下一个代理并重试当前账号。等待邮件验证码不计入此超时。
- **失败切换**：注册接口和临时邮箱接口均使用所选代理。连接失败、请求超时、邮箱读取失败、验证码发送被拒绝或注册被明确拒绝，都会记录原因并切换下一个代理重试当前账号。同一账号保留一条记录；每轮每个代理最多尝试一次，一轮失败后默认等待 5 秒再自动重试。代理全部被删除时任务仍保持运行，可在代理页继续添加，补充后自动续跑。
- **提交结果未知**：注册 POST 已发出而无法确认结果时，保留“结果待核对”，切换代理并继续下一个账号。该用户名不会自动再次提交。进度显示已处理账号数，完成提示分别列出成功和待核对数量。

测速通过代理检查站点连接，实际选中代理后再读取出口 IP。连接、DNS、TLS 握手和证书校验失败会显示具体原因。测速门槛与接口超时自动保存，旧版配置缺少这些值时采用默认值。

未启用代理时，验证码接口明确返回 HTTP 429，会遵守服务器的 Retry-After 或等待提示。其他失败自动重试；“无代理重试间隔”设为 0 时采用默认 5 秒，大于 0 时采用相应分钟数。只有用户主动暂停或停止才阻止任务续跑。

## 请求头与网络详情

“请求头”中可选择请求标识（Safari 兼容 / 原生默认）、语言（系统默认 / 简体中文 / 英文）、响应格式（原生默认 / JSON / JSON 与文本），并添加自定义请求头。同名自定义字段覆盖相应配置。默认配置保留 Safari 兼容、英文和 JSON；配置自动保存并用于后续接口请求，任务运行期间不能更改。“任务 → 使用 Safari 浏览器标识”只切换标识。

“最近请求的配置”显示已使用的 User-Agent、Accept 和 Accept-Language。自动配置未显式覆盖的字段按原生或系统默认显示；不会推测不存在的值。

“网络请求”和“请求详情”显示实际 API 请求的方法、路径、时间、响应状态、配置及脱敏的请求头。状态为“连接失败”表示尚未取得 HTTP 响应。详情不记录查询参数、请求正文、Cookie、Authorization 或自定义凭据头；Origin 和 Referer 移除查询及未知路径，已知敏感输入会脱敏。请求头偏好保存在本机应用设置中。

## 结果与本地数据

- 只有 `/api/user/register` 返回 HTTP 成功且 `success: true` 才记录“注册成功”。
- 提交前先原子保存本地状态。注册 POST 超时、网关异常、缺少明确业务结果或提交后中断时，标记为“结果待核对”，该用户名不会自动重复提交。已经成功的账号也不会自动重复提交。本地记录暂不可写时，任务保持运行并自动重试保存，恢复后继续；提交前保存成功才会发送注册 POST。
- 先在官网核对“结果待核对”的账号，再在记录列表选中该账号，点击“记录核对结果”，标记成功或确认未注册后允许重试。
- 服务器明确拒绝验证码或注册时，日志及记录显示 HTTP 状态和经过脱敏的服务器说明，随后自动重试，便于判断重复账号、验证码失效和频率限制等原因。
- 自动收信只匹配本次发送后的相关验证邮件，排除已知旧邮件；无法确认邮件来源或时间时，可手动输入验证码。
- 密码输入后以明文保存到本机应用数据目录的私有文件，目录权限为 0700、文件权限为 0600，启动时自动恢复；密码框下方显示保存状态。清空密码框会删除该文件。应用不访问钥匙串，旧版钥匙串密码需重新输入。
- 密码和验证码不写入账号记录、日志或 CSV。注册通过独立的原生网络会话进行，不复用浏览器登录信息。
- 数据位于 `~/Library/Application Support/BeautyRegistration/`，包括 `records.json`。旧版记录中的截图仅作为历史附件显示；原生流程不生成注册截图，也不依据旧截图推断账号成功状态。
- Fviainboxes 是公开临时邮箱，不适用于敏感账号。

## 验证与维护

```sh
swift test
```

原生注册逻辑通过 URLSession 访问站点 API；接口或邮箱服务响应变化后需要更新相应适配。完整注册需要实际接收验证码并取得服务器回执，读取接口连接状态不能证明注册成功。

本地构建使用 ad-hoc 签名，未做 Apple Developer ID 签名或公证。分发到其他 Mac 前需要正式签名、公证，并分别构建相应架构。
